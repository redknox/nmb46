# 《放学后，坡道之上》｜编剧创作采访档案

> 状态：**WRITERS’ ROOM REFERENCE / FORMAT LOCKED。**
>
> 本目录保存《放学后，坡道之上》长期创作过程中的编剧采访、阶段性口述史与创作复盘。
>
> 它不是剧情 Canon，不反向约束已经锁定的故事事实；它记录的是：**作品是怎样被写出来的，以及当时参与创作的人为什么那样判断。**

---

## 一、基本形式

本系列以一本真正存在的电视剧专业周刊 / 剧本刊物的创作采访为假想形式。

不是宣传花絮，不要求统一口径，也不把所有参与者的回答编辑成同一个“官方解释”。

采访可以发生在：

- 单集开发中途；
- Gate 通过后；
- Screenplay / Scene Lock 阶段；
- 单集 FINAL 后；
- 季终；
- 后续编剧接手或回看旧集时。

每篇采访必须注明采访发生时的实际创作阶段，使未来读者知道回答者当时**已经知道什么、还不知道什么**。

核心原则：

> **保存创作当时的现在时，不把后来知道的结果伪装成当初就已经想清楚。**

---

## 二、采访中的角色

### 1. 记者

Assistant 可以同时扮演采访记者。

记者不是负责宣传作品，而是负责：

- 提问；
- 追问；
- 要求回答者解释具体创作判断；
- 在必要时拿旧稿、Git 历史、研究资料或已经公开的编剧室讨论作为证据继续追问；
- 指出回答者的记忆与当时记录不一致；
- 允许问题本身带有专业记者的怀疑，而不是默认所有决定都是英明的。

记者可以问：

> “你现在这样说，但当时的旧稿不是这样。什么时候改变的？”

也可以问：

> “这到底是人物自己长出来的，还是编剧后来给决定找理由？”

采访不以维护创作者形象为目的。

### 2. Assistant / 当时参与创作的编剧

Assistant 可以在同一篇采访中从“记者”切换成“当时参与创作的编剧”回答。

回答时必须：

- 只谈自己实际参与或能由公开创作记录确认的部分；
- 不把后来形成的结构伪装成最初设计；
- 可以承认记错、判断错误、旧方案被推翻；
- 可以明确说“这个是对方先提出来的”；
- 不为了使创作过程显得高级而倒推一个整齐的理论。

原则：

> **采访回答可以比成品笨拙，但不能比真实创作过程更聪明。**

### 3. 主创 / 人类编剧

主创可以：

- 与 Assistant 分别回答同一个问题；
- 单独接受采访；
- 接在 Assistant 回答后补充；
- 直接反驳 Assistant 的记忆或理解；
- 对记者的问题只回答一部分；
- 回答“我忘了”“当时就是觉得不对”“没有那么复杂”等。

主创的人肉回答默认按原文刊载。

---

## 三、主创原话保留原则

除非主创明确要求，否则：

> **主创回答不润色、不压缩、不总结、不改写成宣传语言。**

允许保留：

- 口语；
- 重复；
- 停顿感；
- 括号；
- “笑”；
- 临时改口；
- 不完整句；
- 当时的犹豫；
- 与后来结论不同的判断。

如存在明显输入错误但不影响理解，也默认保留；只有主创明确要求校正时才修改。

不得在主创回答后自动添加：

> “这说明了……”

或：

> “换句话说，主创真正想表达的是……”

主创自己说到哪里，采访文本就允许停在哪里。

## 四、允许的采访结构

同一系列采访可以自由使用以下形式，不要求每篇全部出现。

### A｜分别回答

同一个问题分别问主创与 Assistant。

两份答案并列存在，不互相校正。

### B｜单独采访

某一段创作主要由某位参与者推动时，只采访该参与者。

### C｜互为补充

一位回答创作动机，另一位补充：

- 当时的现实资料；
- 被否掉的方案；
- 技术限制；
- 上下游连续性；
- Git 中实际发生的版本变化。

### D｜交叉追问

记者可以在听完一人的回答后转问另一人：

> “他 / 她刚才说当时不是这样。你怎么记得？”

### E｜档案对证

记者可以直接引用或概述旧版本事实：

- 某个 commit；
- 旧 Episode Brief；
- 被废弃的 Beat；
- Research；
- Scene Lock；
- 当时已经公开写下的讨论结论。

用于纠正后见之明和错误记忆。

### F｜编剧分歧

如果当时确实存在不同判断，不把过程重写成“大家从一开始就高度一致”。

允许记录：

- 谁不同意什么；
- 为什么不同意；
- 谁说服了谁；
- 两边都没有说服对方；
- 第三个方案后来自己长出来。

## 五、采访的编辑伦理

### 不造神

禁止把普通试错包装成预谋已久。

例如真实过程如果是：

> 先不知道中元是什么职位 → 调研真实合唱部 → 找到声部长 → 再调研 SSAA → 最后锁 S2

采访就应当这样记录。

不得事后改写成：

> “我们从一开始就精确设计了 S2 来象征她的人物命题。”

### 不统一口径

不同回答之间可以有：

- 记忆差异；
- 价值判断差异；
- 对同一场戏不同的喜欢理由；
- 对最终方案仍然保留的轻微意见。

### 不用采访反向解释剧情

采访可以解释创作过程，但故事本身仍必须首先作为电视剧成立。

不能因为采访里能解释，就允许正片出现观众无法理解的硬逻辑漏洞。

### 不伪造私人思考

采访依据：

- 对话中已经公开表达的创作判断；
- 已落盘的项目文件；
- Git 历史；
- 可核验的研究资料；
- 参与者本人当下愿意公开回答的内容。

不虚构没有留下记录、也没有被参与者公开表达过的“当时内心真正想法”。

---

## 六、推荐的采访时间点

### 单集中途采访

特别适合记录：

- 一个故事刚刚“立住”的时刻；
- 某个角色定位刚锁定；
- 一项现实调研刚刚改变剧情；
- 一个原本漂亮的方案刚被推翻。

此时采访必须保留未知：

> **回答者不知道最终成片会怎样。**

### 单集完成采访

重点可以追问：

- 最终留下了什么；
- 什么被删掉；
- 哪个判断直到逐场阶段才出现；
- 哪个前期设计最后证明是错的。

### 季终采访

可以把早期回答重新拿出来，让创作者面对自己当时的判断。

## 七、文件建议

目录：

`docs/writers-room/creative-interviews/`

推荐稳定文件名：

- `ep04-development-interview.md`
- `ep04-final-interview.md`
- `season-01-retrospective.md`
- 如确有多个明确阶段，可在文件内部按采访日期 / Gate 分节，而不是制造大量碎片版本文件。

采访正文建议包含元数据：

- 采访对象；
- 记者；
- 日期；
- 当时开发阶段；
- 当时权威文本状态；
- 是否为单独回答 / 分别回答 / 联合采访。

Git 继续承担版本历史，不在文件名里堆叠 `v0.1 / v0.2`。

---

## 八、当前栏目精神

> **这不是“成品是怎么被我们计划出来的”。**
>
> **这是“我们当时怎么试、怎么错、怎么查，最后怎么发现这个故事原来应该这样长”。**

记者可以严肃。

回答可以狼狈。

Git 可以拆穿记忆。

参与者不需要拥有同一个答案。

只要诚实地保存：

> **作品真正被写出来的过程。**
