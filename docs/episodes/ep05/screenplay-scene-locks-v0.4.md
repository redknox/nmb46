# S08｜LOCKED｜最后一块景片｜13:55—14:10

## 权威文本组成

S08采用：

- `screenplay-revision-v0.5.md` 的S08主体；
- 叠加 `screenplay-revision-v0.7.md` 的对白与作者解释减法。

## 锁定事实

- 13:55最后主景才从固定位置释放；
- 它沿前面景片使用过的成熟单转路线撤出；
- 第一次常规转向失败；
- 失败不是撞击事故，只是继续转会侵入已经完成的合唱台空间；
- 多次普通尝试仍只是在改变起点、角度、哪一端先走，没有改变“用一次主要旋转完成转向”这个默认动作；
- 13:59确认：景片正面尺寸没变，背部本次加固更厚；
- 14:04有人想到动合唱台；技术学生确认按当前路线，下层也必须让出；
- 若月决定先不动已经完成的合唱台；
- 14:05以后箱子、谱架、小设备逐步清开；
- まあ亚只看，不解题；
- 其他出口被排除；
- 14:10景片安全复位。

## 锁定对白重点

**学生B**

**本校舞台学生**  
按现在这样，下面也得让出来。

**学生B**

**若月**  
先别动这边。

S08不说“40分钟”。

## 锁定减法

不出现：

> `这些动作没有白做。`

不出现：

> `只是一个原本几十秒的动作，开始变成一个真正的问题。`

前者留给后续双转用结果回收，后者留给动作、钟与停顿表达。

理由：现场刚亲手用约24分钟搭完，已经知道“全拆”不是可随意采用的方案；明确数字留给S11真夏到场后的真实决策需要，只说一次。

# 跨场连续性锁定说明

虽然S11尚未整场锁定，但以下信息设计已经随S08—S10锁定，不再回退：

- 13:30开始合唱台搭设；
- 13:54三层合唱台完成并确认；
- 可见搭设过程约24分钟；
- S10只确认“全拆”，不报40分钟；
- S11真夏到场后才问`多久能恢复？`；
- 技术学生答：`四十分钟左右。装回来以后还得重新确认。`；
- 这是事故链中唯一一次明确说出40分钟。

同时锁定工作量区分：

> **事故应急40分钟 = 全拆 + 清出 + 主景通过 + 精确重搭 + 连接 + 复检。**
>
> **演出后的正常约10分钟换场 = 单向拆除 + 模块移开 + 下一项讲台进入。**

两者不冲突。

# 镜头 / 节奏保留要求

S08—S10完整呈现的失败动作最多两次：

1. 第一次常规转向失败；
2. 一次明显改变起转角度仍失败。

其余通过短动作、停、退、钟、报告、空间逐渐清开推进。

真正再次完整展示搬运路径，应留到S14的“双转”。

这样まあ亚的贡献才会被观众感受到是**换了一种动作**，而不是第N次尝试终于成功。
