> 状态：**当前因果基线补丁。**

> 继承 `stage-changeover-causal-model-v0.2.md`；本文件只修正连续性审查后需要明确的舞台状态。与 V0.2 冲突处以本版为准。

## 1. 13:54 合唱台已经完整完成

13:47 的“第一列完成”只是中途 Done。

到 13:54：

- 三层正式合唱台已经全部搭设；
- 连接、固定完成；
- 舞台技术学生完成当轮检查；
- 真夏收到明确的 `合唱台完成` Done。

13:55 最后后部主景才因最后附属件解除而真正能够离开固定位置。

这不是错误顺序。原并行计划本来就建立在“旧版主景即使合唱台完成，也仍能按成熟单转路线通过”的条件上；新版主景背部加厚才让这个条件失效。

因此“常规单转若想给主景让路，就必须拆整组合唱台并恢复约40分钟”现在具有完整物理前提。

## 2. 14:16以后没有未安装合唱台模块

旧稿中的“还没装进去的合唱台模块”取消。

此时停在入口侧的是：

- 谱架；
- 合唱用小设备；
- 为清出主景转向空间而暂时移开的工具 / 箱件。

所以主景一旦解决，后台不存在一组隐藏的合唱台安装任务。

14:34 真夏询问“如果现在出去，后面还要多少”时，剩余工作是：

> **设备归位 + 舞台最后确认 + 人员进入准备。**

不是“继续搭剩余合唱台”。

## 3. 最高一级临时落点

14:52 双转方案执行时，最高一级被抬到：

> **主舞台后区靠内侧的安全临时位。**

该位置同时避开：

- 左侧后台通道；
- 双转需要的横向 pocket；
- 主景第二次旋转轨迹；
- 后续工具箱临时集中位置。

主景完全出去后，最高一级可以从该位置立即回装。

## 4. 左侧工具箱与右侧讲台

14:54 后，为尽快恢复舞台，工具箱临时沿左侧墙边集中：

- 人仍可正常通行；
- 不构成安全通道堵塞；
- 但不再适合下一项讲台这种大件从左侧转入。

因此合唱已经正式开始后，真夏看到现场变化，把下一项讲台从原路线改为：

> **右侧进入。**

这体现现场指挥，不是流程说明。

## 5. TAG 的模块撤离方向

演出后下一项需要平舞台，合唱台正常拆除。

因为右侧正在作为讲台的大件进入路线，刚拆下的最高一级不再往右侧存放。

它先被送到：

> **舞台后区临时存放位。**

这样：

- 右侧 = 下一项讲台进入；
- 左侧 = 工具箱临时靠墙；
- 后区 = 合唱台拆下模块的短时存放；

三条物流互不抢路。

## 6. 当前完整物理链

> 合唱台 13:54 完整 Done → 13:55 最后主景释放 → 新主景背部更厚，常规单转与完整合唱台冲突 → 若按常规路线让路，必须整组拆台并恢复约40分钟 → 否决 → 现场继续优化单转并清出周围空间 → まあ亚提出第一转 + 横移 + 第二转 → 技术学生慢速验证 → 下两层避开，只剩最高一级 → 拆顶层、走双转、主景出去、顶层回装，约10分钟 → 工具箱临时集中左侧 → 15:00完整合唱台可用 → 合唱开始后真夏把下一项讲台改走右侧 → 演出后合唱台拆下模块先放后区，讲台正常从右侧进入。

至此，舞台物件状态与物流路线闭环。
