# 《乃木坂女学院》单集编剧工作流

> 状态：**项目级固定工作流。**
>
> 适用于后续每一集。除非某集有明确特殊原因，不随意跳步或改变顺序。
>
> 目标不是把每一集写成同一种故事，而是用同一种审查方法保证：因果可靠、人物不被剧情工具化、观众能跟上、对白关系正确、情绪不被解释掉。

---

## 总原则

### 1. 传达感受，不传达感悟

观众要知道发生了什么，也要感受到这件事是什么滋味；但角色、镜头和作者不要替观众总结“这件事说明了什么”。

> **观众可以不知道我们的感悟，但不能不知道我们的故事。**

### 2. 人物卡与行为引擎优先于剧情机关

剧情必须从已经成立的人物动机、能力、习惯和关系中长出来。

检查问题：

> **去掉“剧情需要她这样做”以后，她本人还会不会这样做？**

如果答案是否定的，优先怀疑剧情，不先修改人物。

### 3. 能用身体写，就不用心理解释

优先使用：动作、停顿、视线、位置、让路、等待、递东西、走开、没有做某个熟悉动作。

呼应优先用动作，不优先复述前文。

### 4. 中文对白，日本社会关系逻辑

对白使用中文，但人物必须按照日本语境中的内外、亲疏、上下、职位、私人关系和场合组织表达。

具体标准见：`docs/writing/dialogue-principles.md`。

### 5. 群像不等于人人在高潮露脸

角色没有自然理由出现在某场，就允许她不出现。

同一个漂亮的人物动作一旦成立，不因为喜欢就重复；重复会让行为变成标签。

---

# Git 文档版本原则

从本规则生效以后，**Git commit 本身就是版本历史**。不再默认通过不断新增 `v0.1 / v0.2 / v1.3` 文件保存同一文档的每一次变化。

## 1. 同一职能只保留一个稳定文件名

例如一集进入正式开发后，优先使用：

- `beat-sheet.md`
- `scene-list.md`
- `screenplay.md`
- `continuity-review.md`
- `audience-review.md`
- `scene-locks.md`

如果内容发生变化，直接修改原文件并提交。

不要因为一次正常修订就新建：

- `screenplay-v0.5.md`
- `screenplay-v0.6.md`
- `screenplay-revision-v1.2.md`

除非两个文件代表的是**不同职能或真正需要长期并存的分支方案**。

## 2. Commit 是历史版本，文件是当前真相

每次已经确认的阶段性变化，用清楚的 commit message 保存，例如：

- `lock ep06 core incident`
- `repair ep06 continuity`
- `polish ep06 s08-s10 dialogue`
- `finalize ep06 screenplay`

需要回看旧方案时，通过 Git 历史读取该文件在旧 commit 的状态，或比较两个 commit；不要求当前目录同时摆着所有旧版本。

因此：

> **文件回答“现在是什么”；Git 回答“以前是什么”。**

## 3. 重要方案必须进入 Git，不能只存在于聊天

开发早期可以在讨论中探索多个备选方案，不必每个脑暴都提交。

但一旦某个方案达到以下任一状态，就应该更新权威文件并提交：

- 双方明确认可；
- 将成为后续因果的前提；
- 已进入逐场审查；
- 已被标记为锁定；
- 未来可能需要精确回溯。

这样即使以后直接修改同一个文件，旧方案仍然可以从 commit 中完整恢复。

## 4. 新文件只用于新的信息类型

以下情况适合新建文件：

- screenplay 与 continuity review 本来就是不同工作产品；
- 世界观设定与人物卡属于不同长期资料；
- 一个压力测试报告需要长期独立保留；
- 两套真正互斥、需要同时比较的路线暂时并存。

以下情况不适合新建文件：

- 只改了几句对白；
- 修了一个时间点；
- 场次锁从 S10 推进到 S13；
- 同一份母稿吸收了新修订；
- 为了“怕找不到旧版”而复制整份文件。

## 5. Final 不等于复制一份新正文

一集定稿时，原则上只需要：

- 权威 `screenplay.md` 已是最终正文；
- 文件头标记 FINAL / LOCKED；
- 一个语义明确的 final commit。

如果需要 `FINAL.md`，它只承担非常简短的状态索引 / 制作说明，不再重复整份剧本。

## 6. 旧项目文件如何处理

EP05 在本规则建立前已经产生大量版本文件。暂不立即批量删除，避免破坏现有交叉引用和审查记录。

后续如做仓库整理，可以在确认权威正文和必要审查文档后：

- 删除当前分支中已失效的重复版本；
- 依靠 Git 历史继续保留它们；
- 或只保留少量真正具有独立研究价值的压力测试 / 审查文件。

不要为了追求目录整洁，在没有确认引用关系前一次性清空历史文件。

# 标准工作流

## STEP 0｜开发期：允许探索，不急着锁

在单集核心结构尚未稳定时，可以讨论人物、事件、场景、笑点、物理机制和备选路径。

本阶段原则：

- 可以产生多个版本；
- 不因为某个机关“很好用”就强行修改人物；
- 重要物理因果应尽早压力测试；
- 草案可以留在讨论中，不必每次立即进入母稿；
- 一旦结构达到可冻结状态，进入下一步。

---

## STEP 1｜整理 / 更新权威母稿

当主要剧情和关键因果已经达成共识后，收束进该集唯一的权威 screenplay 文件：

`screenplay.md`

如果文件已经存在，**直接修改并提交，不另建版本号文件。**

这一阶段只做**已确认内容的回写**，不趁整理母稿偷偷新增创意。

母稿必须吸收：

- 最新锁定场次；
- 已确认的人物行为修正；
- 已确认对白减法；
- 已确认的因果补丁；
- 已确认的角色删除或出场减少；
- 已确认的视觉信息补充。

目标：所有人从同一份当前文本出发，避免“讨论已经改了，母稿还停在旧版”。

需要查看旧母稿时，读 Git 历史中的旧 commit，而不是保留多份并列正文。

---

## STEP 2｜同步 / 清理旧因果设定

母稿更新后，检查结构说明、因果模型、角色卡和世界观文件中是否仍残留被新版本推翻的旧逻辑。

原则变为：

- 权威长期文档直接更新到当前真相；
- 失效内容从当前文件中删除，不继续用“旧版说明”污染阅读；
- 历史由 Git commit 保留；
- 如果某份旧审查报告本身仍有研究价值，可以独立保留，但必须明确它不是当前剧情来源。

这一步尤其适合清理：

- 已取消的事故根源；
- 已改变的角色功能；
- 已废弃的时间点；
- 已修改的空间路线；
- 已删除的信息漂移 / 误会机制；
- 已被最终剧本推翻的人物成长解释。

---

## STEP 3｜完整连续性审查

这一遍只查**客观世界是否成立**，不评价人物是否感人，也不评价主题。

主要检查：

- 时间：每一场具体时间是否能接上；
- 地点：人物是否可能在这个时间到达这里；
- 人物位置：谁此刻在哪；
- 信息状态：谁知道什么、谁还不知道什么；
- 道具/设施：物件什么时候出现、什么时候移动、什么时候消失；
- 空间：入口、出口、幕、舞台、通道、座席、后台等是否自洽；
- 物理动作：搬运、换台、演出准备是否能实际完成；
- 因果：前面建立的条件，后面有没有忘掉；
- 恢复条件：某个被取消/失败的方案后来恢复时，造成失败的条件是否真的已经消失。

本阶段问题：

> **如果把这集当成真实发生的一天，它能不能按这个顺序真的发生？**

---

## STEP 4｜观众视角审查

这是独立关卡，不能被“编剧自己知道逻辑”代替。

具体方法见：`docs/writing/audience-perspective-review.md`。

审查时暂时忘掉：

- 人物卡；
- 编剧注释；
- 因果模型；
- 创作会议讨论；
- 作者意图；
- “这个动作象征什么”。

只承认观众真正能获得的：

- 画面；
- 对白；
- 声音；
- 剪辑顺序；
- 前面正片已经播出的事实。

每个关键节点问：

1. 观众已经知道什么？
2. 观众可以自然推断什么？
3. 有什么只有编剧知道？
4. 如果第三项是理解故事所必需的信息，必须补桥。

信息分级：

- **A｜必须明白**：不明白就跟不上故事；
- **B｜最好能感觉到**：不必用语言说清，但应该被感受到；
- **C｜只留潜意识**：主题、余韵、象征，不要解释。

审查等级：

- **GREEN**：观众可自然理解；
- **YELLOW**：能猜到，但画面信息不足，优先用视觉/动作补；
- **RED**：只有编剧知道，观众无法理解关键因果，必须修。

修补优先顺序：

> **视觉关系 / 动作 / 空间 / 剪辑 → 极少量功能对白 → 解释性对白（最后手段）**

---

## STEP 5｜逐场锁定

连续性和观众视角通过后，从前往后逐场审查，不一次锁完整集。

推荐按小批次进行，例如 S05—S07、S08—S10。

每场至少过以下四项：

### A. 人物行为引擎

- 去掉剧情功能，她还会这样做吗？
- 有没有临时增加角色原本没有的技能？
- 有没有为了让主要角色露脸而强行出现？
- 有没有为了推进剧情让她突然说/做不像自己的事情？

### B. 日式关系对白

- 她和对方是熟人、前后辈、老师学生、校内校外、职位关系还是私人关系？
- 同一句真实意图，日本人在这个关系里会怎么说？
- 有没有中文式过短、过直、过攻击的表达？
- 有没有为了“日式”而让所有人都变成同一种含糊说法？

### C. 作者解释减法

- 有一句台词只是替观众解释已经看见的东西吗？
- 能否用动作、停顿、视线替代？
- 如果删掉这句话，观众仍然知道发生什么，而且感觉更强吗？

如果是，删。

### D. 观众视角复核

场次单独拿出来时，观众能不能理解当前动作与前文的关系？

尤其注意被删除解释对白以后，不要把A类必要信息也一起删掉。

四项通过后，再进入 scene locks。

锁定后原则：

- 不因后续“想到更漂亮的说法”随便重开；
- 只有发现连续性硬伤、人物硬伤或观众理解RED，才考虑重开；
- 已锁定的优秀对白与动作不重复打磨到失去自然感。

---

## STEP 6｜整集节奏审查

所有场次基本锁定以后，脱离单场视角，从头到尾读完整集。

这一遍只查节奏：

- 哪一段明显太长；
- 连续几场是否都在做同一种事情；
- 同一种人物动作是否重复；
- 是否连续出现多个同性质笑点；
- 情绪有没有一直只升不降；
- 沉重场景后有没有生活自然进入；
- 喜剧有没有为了抖包袱打断真实动作；
- 信息有没有重复交代；
- 群像是否变成轮流点名露脸。

目标不是追求“每分钟都有事”，而是让观众感觉真的和这些人一起过完了一段时间。

---

## STEP 7｜表演与镜头空间审查

最后才检查表演空间，而不是提前把剧本写成镜头说明书。

重点问：

- 哪些对白应该改成停顿？
- 哪些心理应该交给演员眼神？
- 哪个地方应该让角色走掉，而不是再说一句？
- 哪个呼应应该只通过动作出现？
- 有没有不必要的“观众反应镜头”替观众规定情绪？
- 是否给重要演员留下了可以演、但不需要说出来的空间？

尤其保护：

- 无声回收；
- 动作呼应；
- 身体关系；
- 画面先于台词半秒让观众自己理解的瞬间。

---

# 每集完成条件

一集进入“稳定剧本”状态前，应满足：

- 当前母稿和锁定文件一致；
- 旧因果文档已同步或清除失效内容；
- 完整连续性无硬伤；
- A类观众信息全部 GREEN；
- YELLOW 已确认可接受或通过视觉补足；
- 无关键 RED；
- 主要角色行为符合人物引擎；
- 对白符合日本关系逻辑；
- 作者解释已尽量删除；
- 不存在明显重复人物动作 / 功能性露脸；
- 整集节奏回读通过；
- 表演与镜头空间审查通过；
- 权威文件已提交到 Git，commit message 能说明这次确认了什么。

---

# 核心检查句

遇到犹豫时，按顺序问：

> **现实里，这件事发生得通吗？**
>
> **这个人自己会这么做吗？**
>
> **观众真的看得懂吗？**
>
> **日本人在这个关系里会这么说吗？**
>
> **这句话是在传达故事，还是在替观众总结感悟？**
>
> **能不能删掉一句，让感觉反而更强？**

这套流程用于保持整季的一致性，但不要求每集具有相同节奏、结构或主题表达方式。
